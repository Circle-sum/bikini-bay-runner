# 小世界 · 设计稿

> 状态：**v3（2026-10-19）· 已实现** —— 可自由行走的比奇堡海湾 + 撒网抓水母 + 蟹堡王午市 + 空手道棚看破切磋。
> v1 的「点选小地图大厅 + 伪 3D 挥网」已作废（差异见 §8 实现记录）。
>
> 定位：跑酷之外的第二条循环。同一片海、同一批角色，玩法从「往前跑」换成「停下来做点事」。
> 本文只写设计与落点，不写实现细节；数值以 `assets/world/world.js` 的 `WORLD_TUNING`、
> `assets/world/krusty.js` 的 `KRUSTY_TUNING`、`assets/world/dojo.js` 的 `DOJO_BELTS` 为准。

## 0. 已定决策（来自讨论）

| 决策 | 结论 | 影响 |
| --- | --- | --- |
| 入口形态 | **可自由行走的俯视世界**（不是卡片点选） | 一张 2000×1300 的地图 + 镜头跟随 + 碰撞；玩家走到水母田才算「到了」 |
| 抓水母玩法 | **B 撒网为主 + 诱饵加料** | 点哪撒哪（落网罩一圈）；每局 3 个果冻诱饵把水母引团，是连抓的起手 |

| 首批范围 | **v2 先打通抓水母**；v3 补上蟹堡王与空手道棚 | 两栋建筑从「装修中」实体变成可进门的小游戏 |
| 收益节奏 | **不设限**（不做每日/封顶） | 单价压一档，靠单局时长 × 操作难度自然约束 |

| 资产 | **不新增图片** | 海湾、建筑、水母、网、诱饵、两个小游戏界面全部程序化绘制 / CSS + emoji |

## 1. 整体循环

```
                 ┌──────────── 跑酷（现有）────────────┐
                 │  金币 → 贝壳币 · 任务 · 连击 · 事件卡  │
                 └───────────────▲─────────────────────┘
                                 │ 开局道具 / 装饰 / 称号
        ┌────────────────────────┴────────────────────────┐
        │                小世界（可走动）                   │
        │  海湾里走动，三处地点都能进门                        │
        │                                                  │
        │  ① 水母田 ──► 撒网抓水母 ──► 果冻 + 贝壳币          │
        │  ② 蟹堡王 ──► 午市做蟹黄包 ──► 贝壳币               │
        │  ③ 空手道棚 ──► 看破切磋 ──► 段位 + 贝壳币          │
        │                     │                            │
        │                     └──► 反哺跑酷：滑板 / 装饰 / 称号 │
        └──────────────────────────────────────────────────┘
```

要点：

- **和跑酷共用一个世界设定**：跑酷里水母是「要跳过去的危险」，小世界里用网把它抓起来；
  水母霓虹板滑板、水母潮事件卡都能互相呼应。
- **产物反哺跑酷**：三个地点都直接产贝壳币；空手道段位是长期目标（头饰装饰留后续）。
- **不抢跑酷的戏**：水母田单局 45 秒、蟹堡王午市 75 秒、空手道一场约 30~60 秒，
  产出控制在跑一局（金币×1 + 任务）同量级。

## 2. 可走进的海湾（`WorldHub`）

### 2.1 地图与镜头

- **2000×1300 的俯视地图**：西边一片大沙滩，东边一片浅水湾（水母田）。世界坐标与
  `WORLD_MAP` / `WORLD_ISLAND` / `WORLD_LAGOON` 一一对应。
- 起点 `WORLD_START (860, 660)`，正好在沙滩中央、能一眼看见水母田的路牌。
- **镜头缓动跟随**：目标 = 玩家位置 + 面朝方向 24 单位的前瞻，指数缓动
  （`1 - exp(-dt*6)`），再夹在地图边界内。不切镜头、不缩放。
- **海岸线是不规则椭圆拼的**：沙地用 6 块错位椭圆求并集、水母田用 5 块。
  碰撞按同一套几何判定（`inIslandBlobs` / `inLagoon`），走得到的边界和画出来的海岸线一致。
- 地图元素分层（由远到近）：海面（渐变 + 漂浮光斑 + 碎波）→ 沙滩（含浪花虚线）→
  水母田（含波纹与浪花沿）→ 小径 → 路牌 → 装饰/建筑/玩家（按脚底 y 排序）→ 地名浮标。

### 2.2 三处地点（`HUB_SPOTS`）

| 地点 | 坐标 | 状态 | 交互 |
| --- | --- | --- | --- |
| 水母田（路牌） | `1032, 700` | 开放 | 走进浅水自动开局；靠近只显示「水母田 · 下水」 |
| 蟹堡王 | `470, 430`（门口 `470, 500`） | 营业中 | 门口按 E / 空格 / 点门 → 打开午市小游戏 |
| 空手道棚 | `500, 990`（门口 `500, 1060`） | 营业中 | 同上 → 打开看破切磋小游戏 |

- 建筑是**实体**：有体积、挡人（分轴滑动碰撞），门口 130 单位内算「靠近」；
- 营业中的建筑门口挂一块绿色小牌（「营业中」/「切磋中」），靠近时上方浮出名牌气泡
  （`drawNearLabel`），明确告诉玩家「这里能进门」；
- 原先的「装修中 · 敬请期待」胶带与轮换台词已删除，回归断言同步改成「按 E 能进门」。

### 2.3 操作

| 操作 | 键盘 | 触屏 / 鼠标 |
| --- | --- | --- |
| 走动 | `WASD` / 方向键（按住持续走） | 点地走路；按住拖动 = 往拖动方向走 |
| 交互（进门 / 下水） | `E` / `空格` / `Enter` | 点建筑 / 点水母田 |
| 换角色 | `C` | 顶栏「换人」→ 浮层（复用 `.char-card`，只列已解锁角色） |
| 返回标题 | `Esc` | 左上角返回键 |

- **走动是持续的**：`keydown`/`keyup` 记进 `WorldHub.keys`，主循环每帧读；点地走路则把坐标
  存成目标点，走到就停（点地会被新的一帧目标覆盖）。
- **走进浅水即开抓**：`inLagoon(player, 0.9)` 为真时，主循环直接调 `startJellyGame()`，
  同时记下入水点 `lastEntry`——「再抓一网」时就从这儿下水。
- **进门后是世界上的 DOM 全屏层**：`openKrusty()` / `openDojo()` 把 `game.state` 切到
  `krusty` / `dojo`，世界停止更新；蟹堡王里 `Esc` = 提前收摊并结算，空手道里 `Esc` = 退出（不结算）。
- 手机竖屏同样成立：镜头跟随 + 点地走路，没有必须键盘才能做的事。

### 2.4 地图的「活着」感（成本低但效果明显）

- 海面 7 个缓慢漂移的光斑（`lighter` 叠加）与 26 道细碎波纹；
- 水母田 4 圈由内向外扩散的波纹 + 沿岸流动的浪花虚线；
- 棕榈叶、海草随 `t` 摆动；装饰用固定种子（`mulberry32(20261019)`）惰性生成，每次进地图一致；
- `world` 态每帧整帧重绘（先 `clearRect` 再画），元素少、开销固定为一层。

## 3. 抓水母（撒网 + 诱饵）

### 3.1 场景与镜头

- **同一张地图、同一个镜头**：走进浅水就在原地开抓，没有加载、没有切场景；
  镜头仍然是跟随玩家的那一套，只是想看哪就游到哪。
- 玩家从「走」变「游」：速度 205 → **158**，并且被夹在水母田里（`clampToLagoon`），
  涨潮前出不去——想收手就等潮水，或者从暂停里上岸。
- 水母在水里自由游动（缓转向 + 上下浮动），不是「从远处飘过来」：
  撒网是**空间判断**，不是时机判断。

### 3.2 操作

| 操作 | 键盘 | 触屏 / 鼠标 |
| --- | --- | --- |
| 游动 | `WASD` / 方向键 | 拖动 = 游；点一下 = 点地游过去 |
| 撒网 | `空格` / `E` / `Enter` / `→`（按钮） | 点哪撒哪（准星跟着点） |
| 丢诱饵 | `Q` / `B` / 按钮 | 按钮 |
| 暂停 | `P` / `Esc` | 右上角暂停键 |

- **准星**：鼠标/手指最近动过就跟着指针（`aimScreen`），4 秒没动就回到「面朝方向 160 单位」
  （键盘也能玩）；准星画成虚线圆 + 中心点。
- **撒网**（`castAt` / `resolveNet`）：
  - 网从玩家飞向准星，`netFlight 0.24` 秒后落网结算，落网水花留 `netOpen 0.45` 秒；
  - 落网瞬间罩住**半径 84** 内（派宝宝 ×1.25 = 105）的所有水母，一次可以多抓；
  - 撒网距离上限 `netRange 300`，超出会落在范围内、不改方向；
  - 冷却 `netCd 0.62` 秒（碧莲 0.44）；
  - 撒空会清空连抓（有 0.35 秒的「再等等」白圈动画 + 甩网音）——**空网也是失误**。
- **诱饵**（`dropBait`）：每局 3 个，丢在面朝方向 70 单位（会夹在水母田内），
  存在 5 秒、吸引半径 250：范围内的水母亲自游向你丢下的点聚成一团。
  诱饵是**连抓起手**：先聚团、再一网多只，倍率涨得比一只一只抓快得多。

### 3.3 水母表（落地值）

| 类型 | 出现权重 | 果冻 | 行为 | 惩罚 |
| --- | --- | --- | --- | --- |
| 粉水母 | 52% | 1 | 慢悠悠，转向少 | 无（游过去就好） |
| 蓝水母 | 30% | 2 | 更快、左右打转 | 无 |
| 电水母 | 13% | 0 | 最快、爱往你身边凑 | **网到或碰到都会短路 2 秒**：撒不了网、游不动，连抓清零 |
| 黄金水母 | 5% | 5 | 最快、拐弯多 | 无，但会游走（跑得快） |

- 同屏上限 14 只，每 2.1~3.1 秒补一只（开局先撒 7 只，保证第一网有目标）；
- 水母互相不碰撞，碰边（水母田边界）折返；
- 电水母是**走位考验**：网撒出去之前先看清楚圈里有没有它；碰到也会短路，所以别往它身上撞。

### 3.4 连抓

- 连续「有效撒网」累计连抓，倍率：5 连 ×1.5 → 10 连 ×2 → 15 连 ×3（上限 ×3）；
- 一网多只按只数累加连抓（3 只一网 = 连抓 +3）；
- 被电水母短路或撒空 → 连抓清零；
- HUD：顶栏第三格「连抓」+ 下方进度条（下一档倍率的进度）+ 命中飘字（`jelly-pop`）。
  5/10/15 档位跨过时另有横幅提示。

### 3.5 角色差异（语义对齐跑酷技能）

| 跑者 | 跑酷技能语义 | 抓水母里的体现 | 实现 |
| --- | --- | --- | --- |
| 海绵碧莲 | 稳健 / 容错 | 撒网快 | `netCd ×0.7`（0.62 → 0.44） |
| 派宝宝 | 破障 / 直接 | 网口大 | `netR ×1.25`（84 → 105） |
| 章鱼王哥 | 掌控节奏 | 水母变慢 | `speedMul 0.8` |
| 诸葛珊迪 | 路线推演 | 看得见价签 | 黄金/蓝水母头顶挂「+5 / +2」角标 |

四人各有一处差异、互不叠加，数值都在 `JellyGame.tune()` 里。

### 3.6 音效（全部现场合成，无音频文件）

- 撒网：噪声 buffer + 带通；落网命中：短促上扬；
- 诱饵：低频「咕嘟」；黄金水母：三音分解和弦；电水母：低频 buzz + 屏幕轻抖（读 `SETTINGS.vibrate`）；
- 涨潮最后 10 秒有提示飘字，结算沿用成就音。

### 3.7 结算面板（DOM，复用 `.panel` 风格）

```
              完美一网！
   ┌────────┬────────┬──────────┬──────────┐
   │ 12 果冻 │ 7 捕获 │ 15 最高连抓 │ 2 黄金水母 │
   └────────┴────────┴──────────┴──────────┘
   本局 12 个果冻 → 24 贝壳币（完美赏 +12）· 余额 234
   果冻库存 12 · 累计捕获 7 只 · 单局最佳 12 个 · 黄金水母 2 只
   [再抓一网]   [回小世界]
```

- 入账：果冻进存档、贝壳币走 `persistEconomy()`（一次写盘，钱和果冻同生共死，见 §7.4）；
- **完美一网**：零短路且抓到 ≥ 6 只 → 额外 `perfectBonus 12` 贝壳币；
- 结算后玩家被推回岸边（`leaveLagoon`），「回小世界」不会立刻又掉进水里；
- 首次达成 / 新纪录触发成就 toast（复用 `showAchToast`）。

### 3.8 明确不做（本版）

- 不做体力/门票制（决定：不设限）；
- 不做水母图鉴收集（可作后续扩展）；
- 不做双人抓水母；
- 不做「网兜升级 / 泡网」这类养成（留给 M4 之后）。

## 4. 蟹堡王 · 午市做蟹黄包（已实现）

### 4.1 形式与节奏

- **纯 DOM 玩法**：订单卡 + 原料按钮 + 烤盘时机条，像商店界面一样稳，触屏天然适配；
- **一局 = 一个午市（75 秒）**：开局 2 位顾客，最多同时 3 位，每 5.2~7.6 秒补一位；
- 每位顾客带一张 4~5 层的订单（面包-肉饼-生菜/番茄/芝士-面包）和一条耐心条；
- 双份订单（9 层）更赚，但耐心更紧；到点自动走人，连单清零。

### 4.2 操作闭环

| 步骤 | 操作 | 反馈 |
| --- | --- | --- |
| 煎肉饼 | 空格 / 点「煎肉饼」开火，再按一次停指针 | 指针来回扫；中间 ±11% = **金黄**（+2 小费），±28% 内 = 合格，之外 = 糊 |
| 叠料 | 按订单顺序点原料（或 `1`~`5`） | 面包、肉饼、生菜、番茄、芝士；肉饼从备餐台取，备餐台最多存 2 块 |
| 上菜 | 叠到与某张订单完全一致 | 自动上菜，优先耐心最少的那位；多张同配方也按这个规则 |
| 兜底 | `Z` 撤回（碧莲每局 1 次）/ `X` 倒掉 | 错料不扣钱，但会提示「对不上订单」；倒掉可重来 |

### 4.3 压力与连单

- 顾客耐心 17~23 秒（双份 20~25 秒），到点走人；
- 煎糊或顾客走掉都会**清空连单**；
- 连单每 3 单小费 +10%，封顶 +50%；
- 75 秒到 / 点 ✕ 提前收摊 → 结算面板。

### 4.4 角色差异

| 跑者 | 差异 | 数值 |
| --- | --- | --- |
| 海绵碧莲 | 撤回一次 | `undoLeft 1`（只对碧莲生效） |
| 派宝宝 | 煎盘窗口 +30% | `perfectBand / goodBand ×1.3` |
| 章鱼王哥 | 顾客耐心 +25% | `patienceMul 1.25` |
| 诸葛珊迪 | 高亮下一味原料 | 原料按钮加 `.need` |

四人各一处差异、互不叠加，参数在 `KrustyGame.band()` / `patienceMul()` / `sandyHint()`。

### 4.5 结算与存档

```
              午市大卖！
   ┌────────┬────────┬──────────┬──────────┐
   │ 64 收入 │ 9 卖出 │ 5 金黄肉饼 │ 4 最高连单 │
   └────────┴────────┴──────────┴──────────┘
   本局收入 64 贝壳币 · 余额 431
   累计卖出 9 份 · 单局最佳 9 份 · 金黄肉饼 5 个
   [再开一市]   [回小世界]
```

- 收入一次写进钱包与 `SAVE.world`；写盘失败整体回滚，面板提示「存档写入失败，本局收入没有入账」；
- 存档字段：`krustyRuns / krustyServed / krustyBest / krustyPerfect / krustyCoins`；
- 成就：第一份订单（30）、单局 10 份（80）、累计 50 份（120）。

### 4.6 明确不做（本版）

- 不做海之霸捣乱虫、蟹老板催单、假动作订单；
- 不做「必须递给指定顾客」的二次选择（自动上菜优先最急的）；
- 不做一次烤多块（一次一块，备餐台最多存 2 块）；
- 果冻加料 / 消耗果冻开工留后续（当前果冻只计数）。

## 5. 空手道棚 · 看破切磋（已实现）

### 5.1 形式

- **回合制「读招—反制」**：不做实时格斗——成本可控、触屏友好，
  且「在正确窗口做出正确反应」正是跑酷险过 / 完美穿越的核心手感；
- 三局两胜，每回合先到 3 分；
- 对手起手（高踢 / 中拳 / 扫腿）→ 进度条 → 最后一段变红 → 按下对应格挡。

### 5.2 操作与判定

| 输入 | 结果 |
| --- | --- |
| 红区 + 正确格挡 | **看破**：你 +1 分（派宝宝 +2），对手僵直 |
| 正确格挡但按早了 | 只是挡住：不得分，也不挨打 |
| 防错方向 | 对手 +1 分 |
| 窗口结束完全没按 | 对手 +1 分 |

- 键 `1` / `2` / `3`，或点三个大按钮（上段 / 中段 / 下段）；
- 每个回合之间重置比分，三局两胜；`Esc` 中途退出不结算。

### 5.3 段位与难度

| 段位 | 起手 | 看破窗口 | 奖金 |
| --- | --- | --- | --- |
| 白带 | 1.15s | 0.26s | 40 |
| 黄带 | 1.00s | 0.24s | 55 |
| 蓝带 | 0.88s | 0.22s | 70 |
| 红带 | 0.76s | 0.20s | 90 |
| 黑带 | 0.64s | 0.18s | 120 |

## 7. 技术方案

### 7.1 文件与加载

```
assets/world/world.js     海湾 + 抓水母：WORLD_TUNING / WorldHub / JellyGame
assets/world/krusty.js    蟹堡王：KRUSTY_TUNING / KrustyGame
assets/world/dojo.js      空手道棚：DOJO_BELTS / DojoGame
docs/小世界-设计稿.md      本文（不进部署白名单）
```

- 加载顺序：`characters.js` → `world.js` → `krusty.js` → `dojo.js` → 内联主脚本；
- 三个世界脚本都是**经典脚本**，与主脚本共用全局作用域，因此有四条铁律（文件头也写了）：
  1. 顶层只放纯字面量常量（载入时主脚本的 `const` 还在 TDZ，不能调 `clamp()` / `CHARS` / `$()`）；
  2. 所有依赖游戏全局（`game` / `$` / `SAVE` / `AudioSys`）的代码只在运行期被调用；
  3. 需要随机的装饰数据在 `ensure()` 里惰性生成（固定种子，每次进地图一致）；
  4. 小游戏的状态只放在自己的对象里，结算通过 `endKrustyShift` / `endDojoMatch` 交回主脚本；
- 零依赖不变；`index.html` 仍可直接双击打开（`file://` 也能跑），小游戏只用到 DOM。

### 7.2 状态机与接口

`game.state` 新增：`world`（海湾里走动）、`jelly`（抓水母）、`jellyPause`、`jellyOver`、
`krusty`（蟹堡王午市）、`krustyOver`、`dojo`（空手道切磋）、`dojoOver`。

主循环：

| 状态 | 每帧做什么 |
| --- | --- |
| `world` | `WorldHub.update(dt)` + `WorldHub.render()` |
| `jelly` | `WorldHub.update(dt)`（游动/镜头）+ `JellyGame.update(dt)`（玩法）+ `JellyGame.render()` |
| `jellyPause` / `jellyOver` | 静止，只在状态切换时重画一帧 |
| `krusty` | `KrustyGame.update(dt)`（DOM 驱动，不画画布） |
| `krustyOver` | 静止，等结算面板按钮 |
| `dojo` | `DojoGame.update(dt)`（DOM 驱动，不画画布） |
| `dojoOver` | 静止，等结算面板按钮 |

```js
// world.js 实际暴露的对象（接口以这个为准）
const WorldHub = {
  // 生命周期
  enter(), resume(), ready,
  // 输入
  key(k, down), clearKeys(),
  dragStart(x, y), dragMove(x, y), dragEnd(),   // dragEnd 返回位移很小的点按坐标（或 null）
  clickAt(x, y),                                // 点地走路 / 点建筑进门
  interact(),                                   // 与最近的地点互动（键盘 E）
  // 查询
  nearestSpot(), inIsland(x, y, k), inIslandBlobs(x, y, k), inLagoon(x, y, k),
  clampToLagoon(x, y, k), canStand(x, y),
  // 每帧
  update(dt), updateCam(dt), render(),
  // DOM / 提示
  syncBar(), hintFor(), toast(text),
  // 数据
  player, cam, near, tap, picking, lastEntry, spots,
};
const JellyGame = {
  start(), update(dt), render(),
  aimScreen(x, y), castScreen(x, y), swing(),       // 鼠标/触屏/键盘三个入口都落在 castAt
  castAt(x, y), resolveNet(),                       // 撒网→落网结算，测试直调
  dropBait(),
  spawnAt(kind, x, y, opts),                        // 测试用的确定性生成
  tune(),                                           // 当前跑者的手感参数
  chainMul(), stats(),                              // 倍率 / 结算快照
  drawUnder(t), drawOver(t), drawScreen(t),         // 供 WorldHub 分层调用
};
const KrustyGame = {
  start(), update(dt), finish(),                    // finish → endKrustyShift（结算）
  grillAction(), addIngredient(id), undo(), clearStack(),
  spawnOrder(opts),                                 // 测试用的确定性订单
  band(), patienceMul(), sandyHint(), comboMul(),   // 角色加成 / 连单倍率
  stats(),                                          // { earned, served, perfect, burnt, bestCombo }
  orders, tray, stack, time, active, earned,
};
const DojoGame = {
  start(), update(dt), block(side), resolve(kind),  // kind: 'perfect' / 'guard' / 'wrong' / 'hit'
  nextExchange(), cancel(),                         // cancel = 中途退出，不结算
  belt(), tune(), stats(),                          // 当前段位 / 角色参数 / 结算快照
  move, phase, windup, perfect, stage, active,
};
const WORLD_TUNING = { ... };   // 抓水母数值
const KRUSTY_TUNING = { ... };  // 蟹堡王数值
const DOJO_BELTS = [ ... ];     // 五段腰带：起手 / 看破窗口 / 奖金
```

- **分层调用**：`JellyGame.render()` 只是转发 `WorldHub.render()`；玩家画在水母之上、
  网与瞄准画在最上层（`drawUnder` / `drawOver` / `drawScreen`）。
- **可测试性**：玩法逻辑全在 `JellyGame` 上，测试沿用「`page.evaluate` 直调函数」的方式。

### 7.3 渲染

- `world` / `jelly` 都用 `WorldHub.render()`：先 `clearRect`，再做一次世界变换
  （`translate(W/2,H/2) → scale(s) → translate(-cam)`），`s = clamp(min(W,H)/620, 0.62, 1.15)`；
- 深度排序：装饰、建筑、玩家按脚底 `y` 排序后依次绘制；
- 画布是 DPR 感知的（`cx.setTransform(DPR,...)`），所有绘制都在 CSS 像素空间里做；
- 沙地/水母田是**多块椭圆的并集**：`ellipse()` 会给相邻子路径连一条线，
  多条这样的连线会让 nonzero 填充在大块区域里挖出三角形空洞——所以每块椭圆前都补一个
  `moveTo(椭圆起点)`；这条坑在文件里有注释，改动时别删。
- 旧伪 3D 抓水母相关资产（`drawJellyPool` / `drawJellyKind` / `type:'worldjelly'` /
  `game.districtPlan=['jelly']` / `drawPlayer` 的 `jelly` 分支）**已全部删除**。

### 7.4 存档

**果冻与贝壳币同一次写盘**：结算同时改钱包和果冻，如果分成两个 key，写盘失败会出现
「钱扣了果冻没到」或反之。因此世界数据并进 `ECONOMY_KEY`（复用 `persistEconomy` 的回滚语义）。

```js
world: {
  jelly: 0,        // 果冻存量
  jellyRuns: 0,    // 抓水母局数
  jellyCaught: 0,  // 累计捕获（只只）
  jellyBest: 0,    // 单局最多果冻
  jellyGold: 0,    // 累计黄金水母

  krustyRuns: 0,   // 蟹堡王开市局数
  krustyServed: 0, // 累计卖出蟹黄包
  krustyBest: 0,   // 单局最多卖出
  krustyPerfect: 0,// 累计金黄肉饼
  krustyCoins: 0,  // 蟹堡王累计收入

  dojoWins: 0,     // 空手道胜场
  dojoMatches: 0,  // 空手道总场次
  dojoBelt: 0,     // 段位 0~4（白黄蓝红黑）
  dojoBestPerfect: 0, // 单场最多看破
}
```

- 沿用白名单校验风格，数字一律 `count()` 校验；旧存档读入时新字段自动取默认值，无需迁移；
- 段位额外夹在 `0~4`，防止坏存档把 `DOJO_BELTS` 读穿；
- v1 → v2 没有改字段，只是「位置」的含义变了（玩家坐标不存档，进场回到起点）；
- v2 → v3 只**新增**字段（蟹堡王 5 个 + 空手道 4 个），老存档原样可用；
- 三个地点的结算都走同一个 `persistEconomy()`：钱包 + world 一起写，失败一起回滚。

## 10. 风险与取舍

- **工作量**：三个玩法是三套状态机 + 四个界面 + 三份测试。海湾 / 存档 / 结算 / 测试这条流水线
  已经在 v2 跑通，v3 的两个小游戏是复制同一套路（各自一个经典脚本 + 主脚本接线）。
- **`index.html` 的膨胀**：v3 主脚本净增约 300 行（四个 screen 的 DOM、状态机分支、输入、
  结算、成就与存档字段）；玩法本体拆到 `assets/world/krusty.js`（约 410 行）与
  `dojo.js`（约 250 行），`world.js` 约 1400 行。
- **触屏双操作**：抓水母是「游动 + 撒网」两个操作，手机上默认「拖动游 / 点按撒网」；
  两个小游戏是纯按钮，天然适合触屏，不需要虚拟摇杆。
- **不设限的经济**：刷钱的时间成本高于跑酷，风险可控；一旦失衡只调单价。
- **不引入新资产**：全部复用现有立绘与程序化绘制 / CSS + emoji（首屏体积不变，
  PWA 预缓存只多两个 JS）。
