# 小世界 · 设计稿

> 状态：**v2（2026-10-19）· 已实现** —— 可自由行走的比奇堡海湾 + 俯视「撒网 / 诱饵」抓水母。
> v1 的「点选小地图大厅 + 伪 3D 挥网」已作废（差异见 §8 实现记录），本文按 v2 重写。
>
> 定位：跑酷之外的第二条循环。同一片海、同一批角色，玩法从「往前跑」换成「停下来做点事」。
> 本文只写设计与落点，不写实现细节；数值以 `assets/world/world.js` 的 `WORLD_TUNING` 为准。

## 0. 已定决策（来自讨论）

| 决策 | 结论 | 影响 |
| --- | --- | --- |
| 入口形态 | **可自由行走的俯视世界**（不是卡片点选） | 一张 2000×1300 的地图 + 镜头跟随 + 碰撞；玩家走到水母田才算「到了」 |
| 抓水母玩法 | **B 撒网为主 + 诱饵加料** | 点哪撒哪（落网罩一圈）；每局 3 个果冻诱饵把水母引团，是连抓的起手 |
| 单局节奏 | 走进浅水自动开局，**涨潮 45 秒**自动上岸结算 | 「时间到」变成世界内的理由；不切场景、不换镜头 |
| 首批范围 | 先打通「抓水母」 | 蟹堡王、空手道棚实体化但「装修中」：可交互、给台词、不能进 |
| 收益节奏 | **不设限**（不做每日/封顶） | 单价压一档，靠单局时长 × 操作难度自然约束 |
| 代码组织 | 全部新代码进 `assets/world/world.js` | `index.html` 只接状态机、DOM、输入、存档、结算 |
| 资产 | **不新增图片** | 海湾、建筑、水母、网、诱饵全部程序化绘制 |

## 1. 整体循环

```
                 ┌──────────── 跑酷（现有）────────────┐
                 │  金币 → 贝壳币 · 任务 · 连击 · 事件卡  │
                 └───────────────▲─────────────────────┘
                                 │ 开局道具 / 装饰 / 称号
        ┌────────────────────────┴────────────────────────┐
        │                小世界（可走动）                   │
        │  海湾里走动，三处地点都能靠近                        │
        │                                                  │
        │  ① 走进浅水 ──► 撒网抓水母 ──► 水母果冻 ──► ② 加料  │
        │       ▲                        │                 │
        │       │                        ▼                 │
        │  ③ 空手道段位 ──► 奖励/装饰 ◄── 售卖 → 贝壳币      │
        └──────────────────────────────────────────────────┘
```

要点：

- **和跑酷共用一个世界设定**：跑酷里水母是「要跳过去的危险」，小世界里用网把它抓起来；
  水母霓虹板滑板、水母潮事件卡都能互相呼应。
- **产物反哺跑酷**：果冻做加料、蟹黄包换钱、段位给称号/头饰（M2/M3）。
- **不抢跑酷的戏**：单局产出控制在跑一局（金币×1 + 任务）同量级。

## 2. 可走进的海湾（`WorldHub`）

### 2.1 地图与镜头

- **2000×1300 的俯视地图**：西边一片大沙滩，东边一片浅水湾（水母田）。世界坐标与
  `WORLD_MAP` / `WORLD_ISLAND` / `WORLD_LAGOON` 一一对应。
- 起点 `WORLD_START (860, 660)`，正好在沙滩中央、能一眼看见水母田的路牌。
- **镜头缓动跟随**：目标 = 玩家位置 + 面朝方向 24 单位的前瞻，指数缓动
  （`1 - exp(-dt*6)`），再夹在地图边界内。不切镜头、不缩放。
- **海岸线是不规则椭圆拼的**：沙地用 6 块错位椭圆求并集、水母田用 5 块。
  碰撞按同一套几何判定（`inIslandBlobs` / `inLagoon`），走得到的边界和画出来的海岸线一致。
- 地图元素分层（由远到近）：海面（渐变 + 漂浮光斑 + 碎波）→ 沙滩（含浪花虚线）→
  水母田（含波纹与浪花沿）→ 小径 → 路牌 → 装饰/建筑/玩家（按脚底 y 排序）→ 地名浮标。

### 2.2 三处地点（`HUB_SPOTS`）

| 地点 | 坐标 | 状态 | 交互 |
| --- | --- | --- | --- |
| 水母田（路牌） | `1032, 700` | 开放 | 走进浅水自动开局；靠近只显示「水母田 · 下水」 |
| 蟹堡王 | `470, 430`（门口 `470, 500`） | 装修中 | 靠近给台词、按 E 招呼一声，不能进 |
| 空手道棚 | `500, 990`（门口 `500, 1060`） | 装修中 | 同上 |

- 建筑是**实体**：有体积、挡人（分轴滑动碰撞），门口 130 单位内算「靠近」；
- 装修中的建筑身上贴「装修中 · 敬请期待」胶带，靠近弹一句台词（每次按 E 从台词表里轮换）；
- 靠近时建筑上方浮出名牌气泡（`drawNearLabel`），明确告诉玩家「这里能互动/还在装修」。

### 2.3 操作

| 操作 | 键盘 | 触屏 / 鼠标 |
| --- | --- | --- |
| 走动 | `WASD` / 方向键（按住持续走） | 点地走路；按住拖动 = 往拖动方向走 |
| 交互（说话） | `E` / `空格` / `Enter` | 点建筑 |
| 换角色 | `C` | 顶栏「换人」→ 浮层（复用 `.char-card`，只列已解锁角色） |
| 返回标题 | `Esc` | 左上角返回键 |

- **走动是持续的**：`keydown`/`keyup` 记进 `WorldHub.keys`，主循环每帧读；点地走路则把坐标
  存成目标点，走到就停（点地会被新的一帧目标覆盖）。
- **走进浅水即开抓**：`inLagoon(player, 0.9)` 为真时，主循环直接调 `startJellyGame()`，
  同时记下入水点 `lastEntry`——「再抓一网」时就从这儿下水。
- 手机竖屏同样成立：镜头跟随 + 点地走路，没有必须键盘才能做的事。

### 2.4 地图的「活着」感（成本低但效果明显）

- 海面 7 个缓慢漂移的光斑（`lighter` 叠加）与 26 道细碎波纹；
- 水母田 4 圈由内向外扩散的波纹 + 沿岸流动的浪花虚线；
- 棕榈叶、海草随 `t` 摆动；装饰用固定种子（`mulberry32(20261019)`）惰性生成，每次进地图一致；
- `world` 态每帧整帧重绘（先 `clearRect` 再画），元素少、开销固定为一层。

## 3. 抓水母（撒网 + 诱饵）

### 3.1 场景与镜头

- **同一张地图、同一个镜头**：走进浅水就在原地开抓，没有加载、没有切场景；
  镜头仍然是跟随玩家的那一套，只是想看哪就游到哪。
- 玩家从「走」变「游」：速度 205 → **158**，并且被夹在水母田里（`clampToLagoon`），
  涨潮前出不去——想收手就等潮水，或者从暂停里上岸。
- 水母在水里自由游动（缓转向 + 上下浮动），不是「从远处飘过来」：
  撒网是**空间判断**，不是时机判断。

### 3.2 操作

| 操作 | 键盘 | 触屏 / 鼠标 |
| --- | --- | --- |
| 游动 | `WASD` / 方向键 | 拖动 = 游；点一下 = 点地游过去 |
| 撒网 | `空格` / `E` / `Enter` / `→`（按钮） | 点哪撒哪（准星跟着点） |
| 丢诱饵 | `Q` / `B` / 按钮 | 按钮 |
| 暂停 | `P` / `Esc` | 右上角暂停键 |

- **准星**：鼠标/手指最近动过就跟着指针（`aimScreen`），4 秒没动就回到「面朝方向 160 单位」
  （键盘也能玩）；准星画成虚线圆 + 中心点。
- **撒网**（`castAt` / `resolveNet`）：
  - 网从玩家飞向准星，`netFlight 0.24` 秒后落网结算，落网水花留 `netOpen 0.45` 秒；
  - 落网瞬间罩住**半径 84** 内（派宝宝 ×1.25 = 105）的所有水母，一次可以多抓；
  - 撒网距离上限 `netRange 300`，超出会落在范围内、不改方向；
  - 冷却 `netCd 0.62` 秒（碧莲 0.44）；
  - 撒空会清空连抓（有 0.35 秒的「再等等」白圈动画 + 甩网音）——**空网也是失误**。
- **诱饵**（`dropBait`）：每局 3 个，丢在面朝方向 70 单位（会夹在水母田内），
  存在 5 秒、吸引半径 250：范围内的水母亲自游向你丢下的点聚成一团。
  诱饵是**连抓起手**：先聚团、再一网多只，倍率涨得比一只一只抓快得多。

### 3.3 水母表（落地值）

| 类型 | 出现权重 | 果冻 | 行为 | 惩罚 |
| --- | --- | --- | --- | --- |
| 粉水母 | 52% | 1 | 慢悠悠，转向少 | 无（游过去就好） |
| 蓝水母 | 30% | 2 | 更快、左右打转 | 无 |
| 电水母 | 13% | 0 | 最快、爱往你身边凑 | **网到或碰到都会短路 2 秒**：撒不了网、游不动，连抓清零 |
| 黄金水母 | 5% | 5 | 最快、拐弯多 | 无，但会游走（跑得快） |

- 同屏上限 14 只，每 2.1~3.1 秒补一只（开局先撒 7 只，保证第一网有目标）；
- 水母互相不碰撞，碰边（水母田边界）折返；
- 电水母是**走位考验**：网撒出去之前先看清楚圈里有没有它；碰到也会短路，所以别往它身上撞。

### 3.4 连抓

- 连续「有效撒网」累计连抓，倍率：5 连 ×1.5 → 10 连 ×2 → 15 连 ×3（上限 ×3）；
- 一网多只按只数累加连抓（3 只一网 = 连抓 +3）；
- 被电水母短路或撒空 → 连抓清零；
- HUD：顶栏第三格「连抓」+ 下方进度条（下一档倍率的进度）+ 命中飘字（`jelly-pop`）。
  5/10/15 档位跨过时另有横幅提示。

### 3.5 角色差异（语义对齐跑酷技能）

| 跑者 | 跑酷技能语义 | 抓水母里的体现 | 实现 |
| --- | --- | --- | --- |
| 海绵碧莲 | 稳健 / 容错 | 撒网快 | `netCd ×0.7`（0.62 → 0.44） |
| 派宝宝 | 破障 / 直接 | 网口大 | `netR ×1.25`（84 → 105） |
| 章鱼王哥 | 掌控节奏 | 水母变慢 | `speedMul 0.8` |
| 诸葛珊迪 | 路线推演 | 看得见价签 | 黄金/蓝水母头顶挂「+5 / +2」角标 |

四人各有一处差异、互不叠加，数值都在 `JellyGame.tune()` 里。

### 3.6 音效（全部现场合成，无音频文件）

- 撒网：噪声 buffer + 带通；落网命中：短促上扬；
- 诱饵：低频「咕嘟」；黄金水母：三音分解和弦；电水母：低频 buzz + 屏幕轻抖（读 `SETTINGS.vibrate`）；
- 涨潮最后 10 秒有提示飘字，结算沿用成就音。

### 3.7 结算面板（DOM，复用 `.panel` 风格）

```
              完美一网！
   ┌────────┬────────┬──────────┬──────────┐
   │ 12 果冻 │ 7 捕获 │ 15 最高连抓 │ 2 黄金水母 │
   └────────┴────────┴──────────┴──────────┘
   本局 12 个果冻 → 24 贝壳币（完美赏 +12）· 余额 234
   果冻库存 12 · 累计捕获 7 只 · 单局最佳 12 个 · 黄金水母 2 只
   [再抓一网]   [回小世界]
```

- 入账：果冻进存档、贝壳币走 `persistEconomy()`（一次写盘，钱和果冻同生共死，见 §7.4）；
- **完美一网**：零短路且抓到 ≥ 6 只 → 额外 `perfectBonus 12` 贝壳币；
- 结算后玩家被推回岸边（`leaveLagoon`），「回小世界」不会立刻又掉进水里；
- 首次达成 / 新纪录触发成就 toast（复用 `showAchToast`）。

### 3.8 明确不做（本版）

- 不做体力/门票制（决定：不设限）；
- 不做水母图鉴收集（可作后续扩展）；
- 不做双人抓水母；
- 不做「网兜升级 / 泡网」这类养成（留给 M4 之后）。

## 4. 做蟹黄包（M2 草图，开工前再细化）

- **形式**：纯 DOM 玩法（订单卡 + 原料按钮 + 烤盘时机条），像商店界面一样稳，触屏天然适配；
- **一局 = 一个午市（约 75 秒）**：顾客订单排队（配方 + 耐心条）→ 肉饼上烤盘「翻面」（来回时机条：绿区金黄 / 黄区合格 / 错过糊掉）→ 按配方顺序点原料 → 递给对应顾客；
- **压力**：订单逐渐变长、错料要重做、**海之霸捣乱虫**（3 秒内点掉，否则抢走一份）、蟹老板偶尔催单（缩短耐心）；
- **角色差异**：派宝宝翻面窗口 +30%；碧莲点错可撤回一次；王哥顾客耐心 +25% 但自身动作慢 10%；珊迪提示下一步原料；
- **结算**：完美 ×6 / 合格 ×4 / 糊 ×1 贝壳币，小费另计；带果冻开工则每份 ×1.5（消耗果冻 1/份）；
- 地点：蟹堡王，进门方式沿用「走近门口 + 交互」；
- 命名待定：招牌写「蟹黄包」还是对齐官方译名「蟹黄堡」（见 §9）。

## 5. 空手道切磋（M3 草图，开工前再细化）

- **形式**：回合制「读招—反制」（不做实时格斗：成本可控、触屏友好，且「在正确窗口做出正确反应」正是跑酷险过/完美穿越的核心手感）；
- **回合节奏**：对手起手 0.4~0.9 秒的预备动作（高踢/中拳/扫腿）→ 按 `1/2/3` 或点三个大按钮对应格挡 → **动作变红后 0.18 秒内按下 = 看破**，直接反制得分；3 回合 2 胜，每回合先到 3 分者胜；
- **段位**：白带 → 黄带 → 蓝带（引入假动作）→ 红带（连招）→ 黑带（提速 + 假动作 + 骗抢拍）；
- **选人**：自己的跑者沿用解锁状态；**对手三位即使锁定也能选来陪练**（试玩未购买的角色，顺便是转化钩子）；
- **奖励**：升段发贝壳币；黑带解锁「空手道头饰」装饰 + 结算页称号「黑带跑者」；
- 地点：空手道棚。

## 6. 经济与数值

| 来源 | 时长 | 单局产出 | 对照 |
| --- | --- | --- | --- |
| 抓水母 | 45s | 果冻 10~30 + 贝壳币 10~30（+ 完美赏 12） | 跑一局：金币×1 + 任务 3×20 |
| 做蟹黄包 | 75s | 贝壳币 30~60（果冻加料更高） | 同上 |
| 空手道 | 60s | 升段一次性奖励；平时少量 | 成就奖励 30~200 的量级 |

- 果冻兑换贝壳币是 **1:1**（结算时按本局果冻数直接折成贝壳币）；
- 决定「不设限」，所以**单价刻意压低一档**：抓一局 ≈ 跑一分钟，且需要真实操作时长；
- 后续如果发现还是高了，**优先调单价/完美赏**，而不是加每日限制；
- 新增消耗口：果冻（M2 加料消耗）本身就是软消耗。

## 7. 技术方案

### 7.1 文件与加载

```
assets/world/world.js     小世界全部新代码：WORLD_TUNING / WorldHub / JellyGame
docs/小世界-设计稿.md      本文（不进部署白名单）
```

- 加载顺序与 `characters.js` 一致：先 `characters.js` → `world.js` → 内联主脚本；
- `world.js` 是**经典脚本**，与主脚本共用全局作用域，因此有三条铁律（文件头也写了）：
  1. 顶层只放纯字面量常量（载入时主脚本的 `const` 还在 TDZ，不能调 `clamp()` / `CHARS`）；
  2. 所有依赖游戏全局的函数都只在运行期被调用；
  3. 需要随机的装饰数据在 `ensure()` 里惰性生成（固定种子，每次进地图一致）。
- 零依赖不变；`index.html` 仍可直接双击打开（`file://` 也能跑）。

### 7.2 状态机与接口

`game.state` 新增：`world`（海湾里走动）、`jelly`（抓水母）、`jellyPause`、`jellyOver`。

主循环：

| 状态 | 每帧做什么 |
| --- | --- |
| `world` | `WorldHub.update(dt)` + `WorldHub.render()` |
| `jelly` | `WorldHub.update(dt)`（游动/镜头）+ `JellyGame.update(dt)`（玩法）+ `JellyGame.render()` |
| `jellyPause` / `jellyOver` | 静止，只在状态切换时重画一帧 |

```js
// world.js 实际暴露的对象（接口以这个为准）
const WorldHub = {
  // 生命周期
  enter(), resume(), ready,
  // 输入
  key(k, down), clearKeys(),
  dragStart(x, y), dragMove(x, y), dragEnd(),   // dragEnd 返回位移很小的点按坐标（或 null）
  clickAt(x, y),                                // 点地走路 / 点建筑说话
  interact(),                                   // 与最近的地点互动（键盘 E）
  // 查询
  nearestSpot(), inIsland(x, y, k), inIslandBlobs(x, y, k), inLagoon(x, y, k),
  clampToLagoon(x, y, k), canStand(x, y),
  // 每帧
  update(dt), updateCam(dt), render(),
  // DOM / 提示
  syncBar(), hintFor(), toast(text),
  // 数据
  player, cam, near, tap, picking, lastEntry, spots,
};
const JellyGame = {
  start(), update(dt), render(),
  aimScreen(x, y), castScreen(x, y), swing(),       // 鼠标/触屏/键盘三个入口都落在 castAt
  castAt(x, y), resolveNet(),                       // 撒网→落网结算，测试直调
  dropBait(),
  spawnAt(kind, x, y, opts),                        // 测试用的确定性生成
  tune(),                                           // 当前跑者的手感参数
  chainMul(), stats(),                              // 倍率 / 结算快照
  drawUnder(t), drawOver(t), drawScreen(t),         // 供 WorldHub 分层调用
};
const WORLD_TUNING = { ... }; // 所有数值集中在这里
```

- **分层调用**：`JellyGame.render()` 只是转发 `WorldHub.render()`；玩家画在水母之上、
  网与瞄准画在最上层（`drawUnder` / `drawOver` / `drawScreen`）。
- **可测试性**：玩法逻辑全在 `JellyGame` 上，测试沿用「`page.evaluate` 直调函数」的方式。

### 7.3 渲染

- `world` / `jelly` 都用 `WorldHub.render()`：先 `clearRect`，再做一次世界变换
  （`translate(W/2,H/2) → scale(s) → translate(-cam)`），`s = clamp(min(W,H)/620, 0.62, 1.15)`；
- 深度排序：装饰、建筑、玩家按脚底 `y` 排序后依次绘制；
- 画布是 DPR 感知的（`cx.setTransform(DPR,...)`），所有绘制都在 CSS 像素空间里做；
- 沙地/水母田是**多块椭圆的并集**：`ellipse()` 会给相邻子路径连一条线，
  多条这样的连线会让 nonzero 填充在大块区域里挖出三角形空洞——所以每块椭圆前都补一个
  `moveTo(椭圆起点)`；这条坑在文件里有注释，改动时别删。
- 旧伪 3D 抓水母相关资产（`drawJellyPool` / `drawJellyKind` / `type:'worldjelly'` /
  `game.districtPlan=['jelly']` / `drawPlayer` 的 `jelly` 分支）**已全部删除**。

### 7.4 存档

**果冻与贝壳币同一次写盘**：结算同时改钱包和果冻，如果分成两个 key，写盘失败会出现
「钱扣了果冻没到」或反之。因此世界数据并进 `ECONOMY_KEY`（复用 `persistEconomy` 的回滚语义）。

```js
world: {
  jelly: 0,        // 果冻存量
  jellyRuns: 0,    // 抓水母局数
  jellyCaught: 0,  // 累计捕获（只只）
  jellyBest: 0,    // 单局最多果冻
  jellyGold: 0,    // 累计黄金水母
}
```

- 沿用白名单校验风格，数字一律 `count()` 校验；旧存档读入时新字段自动取默认值，无需迁移；
- v1 → v2 没有改字段，只是「位置」的含义变了（玩家坐标不存档，进场回到起点）。

### 7.5 成就与生涯

- `ACHIEVEMENTS` 四条（本版沿用）：初次抓水母（30）、单局 18 果冻（80）、
  **累计** 3 只黄金水母（100）、累计捕获 100 只（120）；四条都读 `SAVE.world`；
- 水母田数据没有并进 `STAT_KEYS` / `emptyStats()`（那套是跑酷生涯，由 `recordRunStats` 维护）；
- `renderStats()` 有「抓水母局数 / 累计捕获 / 单局最多果冻 / 黄金水母」四行。

## 10. 风险与取舍

- **工作量**：三个玩法是三套状态机 + 三个界面 + 三份测试。先把「海湾 + 存档 + 结算 + 测试」
  这条流水线跑通，M2/M3 复制套路。
- **`index.html` 的膨胀**：本版主脚本净增约 200 行（状态机分支、HUD、结算、输入）；
  玩法本体全部在 `assets/world/world.js`（约 1300 行）。
- **触屏双操作**：抓水母是「游动 + 撒网」两个操作，手机上默认「拖动游 / 点按撒网」；
  因为点哪撒哪，实操里点一下就撒网是自然的，不会和拖动打架。
- **不设限的经济**：刷钱的时间成本高于跑酷，风险可控；一旦失衡只调单价。
- **不引入新资产**：全部复用现有立绘与程序化绘制（首屏体积不变，PWA 预缓存只多一个 JS）。
